# Windows, приложения и доступы

## Где выполняется Codex

| Среда | Что доступно |
| --- | --- |
| Codex локально на Windows | Файлы и программы этого компьютера в пределах выданных разрешений |
| Codex внутри WSL | Файлы и программы Linux; пути Windows требуют отдельного учёта |
| Codex Cloud | Файлы, процессы и сеть облачной машины; ваш компьютер автоматически не подключается |

В этой задаче проверена облачная Linux-машина. Проверка на вашем Windows-компьютере ещё не выполнялась. Команды в README рассчитаны на PowerShell и нативный Python. Не смешивайте пути `C:\...` и `/mnt/c/...` в одной конфигурации.

## Подключить приложение или сервис

1. Определите приложение, аккаунт, место выполнения и необходимые операции: например, чтение выбранной папки Google Drive.
2. Если в клиенте Codex доступно приложение или плагин для сервиса, подключите его через интерфейс и выполните OAuth-вход. Названия и доступность разделов зависят от клиента и аккаунта.
3. Для своего сервиса или локальной программы используйте официальный либо проверенный MCP-сервер. Примеры находятся в [integrations](../integrations/README.md).
4. Выполните безвредный запрос чтения к нужному ресурсу. Успешная установка не подтверждает доступ к аккаунту.
5. Запишите только метаданные доступа в личный `.local/access.json`, используя `integrations/access.example.json` как образец.

Для управления локальной программой нужен запущенный на Windows инструмент или MCP-сервер, который поддерживает именно эту программу. Доступ к файлам не даёт управление её интерфейсом. Не публикуйте локальный сервер в Интернет ради подключения облака; для удалённого доступа требуется отдельно спроектированная аутентификация и защищённый транспорт.

## Секреты

- Используйте OAuth, системное хранилище учётных данных или защищённые настройки облачной среды. Не отправляйте ключи в чат.
- Для HTTP MCP с bearer-аутентификацией укажите имя переменной через `bearer_token_env_var`; её значение хранится вне Git. Не помещайте токен в аргументы команды, URL или отслеживаемый TOML.
- Codex автоматически не загружает `.env`. Если конкретное приложение использует `.env`, его загрузку выполняет само приложение или его документированный launcher.
- `.gitignore` исключает типичные локальные файлы, но не обнаруживает все секреты. Проверяйте diff перед коммитом. Если ключ уже опубликован, отзовите его в сервисе.
- При удалении подключения отзовите выданное OAuth-разрешение или токен в самом сервисе.

## Облако и сеть

Сетевые правила, OAuth и секреты облачной среды настраиваются в настройках среды/клиента. `.codex/config.toml` не отменяет сетевую политику платформы. Добавляйте только домены нужного сервиса и его авторизации, сохраняйте проверку TLS. Не копируйте облачную аутентификацию в репозиторий или на компьютер.

Для этого проекта дополнительные ключи и сетевые разрешения пока не нужны. Конкретные сторонние приложения пользователь ещё не выбрал, поэтому подключения к ним не создавались.
