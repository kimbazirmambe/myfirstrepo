# Найти статьи и создать пост

1. Откройте **Источники новостей**, войдите как администратор. Добавьте сайт, например `https://podelu.by/`, и ключевые слова, например **банкротства**. Сохранение активного источника с ключевыми словами создаёт задание на поиск по архиву. При изменении адреса или слов незавершённый предыдущий поиск останавливается, начинается новый.
2. Откройте **Найденные статьи** → ссылку на поисковое задание. Здесь видны совпадения, число проверенных страниц, ошибки и ограничения. Можно отдельно нажать **Найти статьи на сайте** и задать другой запрос, не меняя источник. Несколько слов ищутся вместе; варианты через запятую — любой из них. Русские формы слов приводятся к основе: «банкротства», «банкротство», «банкротстве». Исключающие слова источника учитываются; семантический поиск и поиск синонимов не выполняются.
3. Сборщик GitHub Actions запускается примерно раз в 15 минут. В одном запуске проверяет до 60 страниц; архив из 432 страниц потребует нескольких запусков. Сначала проверяются адреса, похожие на запрос. Обновляйте страницу задания. Завершённым без пропусков считается только поиск, проверивший все обнаруженные адреса без ошибок и ограничений. Задержки расписания Actions возможны. Если источник отключён, поиск приостанавливается.
4. Откройте найденную статью → **Сгенерировать пост** → выберите соцсеть, email или мессенджер (Telegram), укажите название редакции. Подтвердите передачу общедоступного текста провайдеру. Это отдельное действие: добавление статьи больше не создаёт новые фактические шаблоны или автоматические ИИ-запросы. Старые черновики сохранены.
5. После ближайшего запуска сборщика откройте результат запроса генерации. Готовый черновик можно редактировать, проверять, утверждать и экспортировать. Старые ручные тексты не заменяются. Источник и ссылка добавляются самим приложением. Отправки в соцсети и рассылки нет.

## Бесплатный ИИ

Поддержан **Gemini 3.5 Flash-Lite** через Google AI Studio. У модели есть Free Tier, но квоты и поддерживаемые регионы меняются. Беларусь отсутствует в опубликованном списке доступных регионов на момент проверки 10 ноября 2026 года. Проверяйте доступность для своего аккаунта; обход региональных ограничений не предусмотрен.

Если сервис доступен:

1. Откройте https://aistudio.google.com/api-keys и создайте ключ **в проекте без платного биллинга**. Не включайте billing и не используйте ключ проекта с оплатой: сам API не позволяет приложению принудительно отличить бесплатный ключ от платного.
2. В GitHub откройте репозиторий → Settings → Secrets and variables → Actions → New repository secret.
3. Имя: `MARKETING_GEMINI_KEY`. Значение: ваш ключ. Сохраните. Ключ не нужно передавать в чат или добавлять в PythonAnywhere.
4. Повторите запрос генерации на сайте. Без ключа появится «Нужно подключить ИИ»; при исчерпании квоты — понятная ошибка. Платного провайдера, переключения модели или автоматического пополнения нет. Генерация одного выбранного формата — один API-запрос; не больше трёх таких запросов за запуск сборщика.

Google может использовать данные Free Tier для улучшения своих сервисов. Отправляется только общедоступный текст статьи, её заголовок, дата, ссылка и указанное название редакции. Подписчики, пароли и пользовательские заметки не отправляются. Провайдер не подтверждает фактическую точность; проверяет редактор. Пока реальный ключ не подключён и успешный ответ не получен, интеграция считается проверенной только автоматическими тестами с подменёнными ответами.

Официальные условия: https://ai.google.dev/gemini-api/docs/pricing и https://ai.google.dev/gemini-api/docs/available-regions . При недоступности провайдера поиск и ручное редактирование продолжают работать.

## Что именно проверяется

Для podelu.by используется публичный `/sitemap.xml`, затем обычный HTML `/article/...`. `/search`, `/api`, авторизация, CAPTCHA и подписные материалы не обходятся. robots.txt проверяется перед запросами; интервал не меньше секунды, учитывается Crawl-delay. Sitemap не гарантирует наличие всех материалов сайта: недоступные страницы, неполный sitemap, ошибки и лимиты отображаются явно. Дата берётся из статьи/JSON-LD, а не из lastmod sitemap.

В SQLite сохраняются только совпавшие статьи (уникальный нормализованный URL), доступный текст для обработки до 30 000 символов и результаты поиска. Текст не показывается публично и не копируется целиком в пост. Если текст обрезан, поиск отмечается как неполный, а генерация по нему запрещается. Большие архивы ограничены 1000 адресами и пятью sitemap; специфической разметке другого сайта может потребоваться отдельный обработчик.

Рабочие задания и приём результатов защищены существующим машинным ключом; веб-страницы — стандартным Django staff-входом и CSRF. Приём пакета проверяет порядок URL и курсор, повторный результат не создаёт дубликаты. Незавершённый поиск можно остановить. PythonAnywhere Beginner обслуживает интерфейс и SQLite; HTTP-сбор и ИИ-запросы выполняются внешним Linux runner GitHub Actions.
