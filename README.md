# myfirstrepo — рабочая среда Codex

Marketing Hub — основа веб-сервиса для маркетинга и продаж на Python 3.12, Django 5.2 LTS и SQLite. Доступны главная страница и раздел «Источники новостей». Существующие инструменты Codex сохранены.


## Запуск Marketing Hub

Нужны Python 3.12 и Git. Команды выполняйте из корня репозитория.

### Windows (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe src/manage.py migrate
.\.venv\Scripts\python.exe src/manage.py runserver
```

### Linux / macOS

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python src/manage.py migrate
.venv/bin/python src/manage.py runserver
```

Откройте в браузере **http://127.0.0.1:8000/** на том же компьютере, где запущен сервер. Для остановки нажмите Ctrl+C. При последующих запусках достаточно последней команды. Повторно устанавливайте зависимости, если изменился requirements.txt; выполняйте migrate после добавления миграций.

Если запускаете приложение в Codex Cloud, адрес 127.0.0.1 относится к облачной машине, а не к вашему компьютеру. Для просмотра на своём компьютере запустите проект локально по инструкции выше. Возможность предпросмотра в облаке зависит от клиента.

SQLite хранит локальные данные в `src/db.sqlite3` (исключён из Git); `migrate` создаёт служебные таблицы Django. Учебные и реальные данные не добавляются. По умолчанию используется режим локальной разработки: DEBUG включён, разрешены локальные адреса, временный ключ меняется при перезапуске. Для публикации предусмотрен отдельный режим production.

Доступны «Главная» и «Источники новостей» (`/sources/`). Остальные пункты меню пока недоступны. Сбора новостей, генерации, входа пользователей и отправок пока нет. Интерфейс использует локальные стили без CDN, API и внешних шрифтов.

### Источники новостей

Откройте пункт «Источники новостей» в меню. Введите название, URL RSS-ленты и при необходимости снимите флажок «Активен», затем нажмите «Добавить источник». Адрес проверяется по формату, разрешены только HTTP и HTTPS; доступность и RSS-содержимое не проверяются, сетевых запросов нет. Флажок пока только сохраняет состояние источника.

Для удаления нажмите «Удалить» у нужного источника, затем подтвердите действие на отдельной странице. Переход на страницу подтверждения ничего не удаляет. Источники сохраняются в SQLite и остаются после перезапуска. Реальные источники и начальные данные не добавляются.

После получения этих изменений выполните `python src/manage.py migrate` выбранным Python из виртуального окружения, чтобы создать таблицу источников. На PythonAnywhere используйте шаг 3 инструкции ниже с существующими секретными настройками, затем collectstatic и Reload, когда решите обновить сайт.

Авторизации по условиям текущего этапа нет: любой посетитель доступного сайта сможет добавлять и удалять источники. Для работы с настоящими данными потребуется ограничение доступа; текущий вариант предназначен для тестирования.

### Проверки

Для Linux / macOS (на Windows замените `.venv/bin/python` на `.\.venv\Scripts\python.exe`):

```sh
.venv/bin/python src/manage.py check
.venv/bin/python src/manage.py test tests/web -v 2
.venv/bin/python scripts/workspace.py check
.venv/bin/python -m unittest discover -s tests -v
```

Тесты веб-приложения запускаются отдельно через Django: `tests/web` намеренно не является Python-пакетом, чтобы существующий unittest-запуск служебных тестов не требовал инициализации Django. Веб-тест проверяет ответ главной страницы, шаблон и все пункты меню. GitHub Actions выполняет обе группы проверок на Python 3.12 в Linux и Windows.

### Файлы приложения

- `src/manage.py` — команды запуска, проверок и создания таблиц.
- `src/marketing_hub/` — настройки Django, SQLite, маршруты и точки запуска сервера.
- `src/dashboard/views.py` — обработка запроса главной страницы.
- `src/dashboard/templates/dashboard/home.html` — разметка главной страницы.
- `src/dashboard/static/dashboard/style.css` — оформление и адаптация для узкого экрана.
- `src/sources/` — модель, форма, страницы и миграция таблицы RSS-источников.
- `tests/web/` — тесты главной страницы, настроек публикации и источников.
- `requirements.txt` — закреплённые версии зависимостей.

## Публикация на PythonAnywhere

Пошаговая инструкция через браузер: [docs/pythonanywhere.md](docs/pythonanywhere.md). Ничего не публикуется автоматически.

| Переменная | Локально | На опубликованном сайте |
| --- | --- | --- |
| `DJANGO_ENV` | `development` по умолчанию | `production`: DEBUG выключен, включены HTTPS и защищённые cookies |
| `DJANGO_SECRET_KEY` | Необязательна; временный ключ | Обязательный постоянный секрет вне Git |
| `DJANGO_ALLOWED_HOSTS` | По умолчанию localhost и loopback | Обязательный точный домен; несколько доменов через запятую |

В production запуск без ключа или домена завершается ошибкой. CSS собирается командой `collectstatic` в игнорируемую папку `.local/static` и раздаётся хостингом по `/static/`. Локальные команды запуска остаются прежними. Тесты в `tests/web` проверяют также HTTPS, допустимые домены, обязательность секрета и сборку CSS.

## Инструменты Codex: начало на Windows

Установите Git, Python 3.11+ и Codex по [официальной инструкции](https://developers.openai.com/codex/windows). Откройте PowerShell:

```powershell
git clone https://github.com/kimbazirmambe/myfirstrepo.git
cd myfirstrepo
python scripts/workspace.py check
python -m unittest discover -s tests -v
codex
```

Если Python доступен как `py`, используйте `py -3.11` вместо `python`. Уже скачанный проект клонировать не нужно. При запросе Codex подтвердите доверие к проверенному каталогу: проектная конфигурация может не загружаться до этого.

## Добавить расширение

```powershell
python scripts/workspace.py new-agent researcher
python scripts/workspace.py new-skill release-check
python scripts/workspace.py new-plugin my-tools
python scripts/workspace.py check
```

Генераторы не перезаписывают файлы. Новая роль регистрируется в конфигурации, плагин — в каталоге. Отредактируйте инструкции под задачу и начните новую сессию Codex.

Пример задания: «Изучи проект ролью explorer, реализуй изменение ролью developer и проверь ролью reviewer». Поддержка параллельных агентов зависит от клиента и политики сессии.
