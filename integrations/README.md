# MCP: подключение инструментов

## Работающий локальный пример на Windows

`scripts/repo_mcp.py` — минимальный MCP-сервер stdio на стандартной библиотеке Python. Он предоставляет инструмент `repository_info`: название checkout и команды проверки. Сервер не читает произвольные файлы, не запускает shell и не использует сеть. Это учебная основа, а не универсальный сервер для управления компьютером.

Из корня проекта в PowerShell:

```powershell
$PythonExe = python -c "import sys; print(sys.executable)"
$ServerPath = (Resolve-Path .\scripts\repo_mcp.py).Path
codex mcp add myfirstrepo-tools -- "$PythonExe" "$ServerPath"
codex mcp get myfirstrepo-tools
```

Если используете Python Launcher, замените первую команду на `$PythonExe = py -3.11 -c "import sys; print(sys.executable)"`. Абсолютные пути позволяют запускать сервер из любого рабочего каталога. Команда `mcp add` сохраняет личную настройку Codex на той машине, где её запустили; в этой облачной задаче личная конфигурация вашего Windows не менялась.

Начните новую сессию Codex и попросите: «Вызови repository_info через myfirstrepo-tools». Для удаления: `codex mcp remove myfirstrepo-tools`.

## Удалённый сервис

Получите адрес MCP из официальной документации выбранного провайдера. Для сервера с OAuth команда выглядит так (сначала замените адрес):

```powershell
codex mcp add service-name --url https://service.example.com/mcp
codex mcp login service-name
```

`service.example.com` — заглушка, а не рабочая интеграция. Для сервера с bearer-токеном используйте настройку `bearer_token_env_var` из `mcp.example.toml` и защищённый источник переменной. Поддерживаемый тип авторизации определяет провайдер. После авторизации проверьте доступ конкретным запросом чтения.

`mcp.example.toml` не загружается автоматически и содержит отключённые примеры. Переносите только выбранную секцию в личную конфигурацию Codex (`~/.codex/config.toml`, обычно в профиле пользователя Windows), сохраняя существующие настройки. Общие несекретные настройки могут жить в проектной `.codex/config.toml`; личные аккаунты туда не добавляйте.

## Разработка своего сервера

Сначала опишите конкретный инструмент и его входную схему. Добавьте реализацию и тесты успешного запроса, ошибок и границ доступа. Для полноценного сервера с OAuth, файлами, несколькими ресурсами или HTTP используйте официальный MCP SDK и закрепите зависимости. Не превращайте пример в неограниченный shell endpoint.

Текущий пример проверяется end-to-end: запуск процесса, initialize, tools/list, tools/call, ошибки параметров и неизвестных инструментов. Поддерживаются версии протокола 2024-11-05, 2025-03-26 и 2025-06-18.
